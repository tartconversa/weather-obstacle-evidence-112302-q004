# 资料契约

本目录只含本地合成记录，不包含真实驾驶员、车辆或道路资料。新闻报道描述的是厂商发布信息及公开说明，不是本资料集中的实测结论。

| 文件 | 字段 | 记录数 | 必需 |
| --- | --- | ---: | --- |
| `visibility.csv` | `sensor_id`, `region`, `observed_at`, `visibility_km`, `observation_quality`, `coverage_fraction` | 47 | 是 |
| `drives.csv` | `trip_id`, `version`, `vehicle_id`, `region`, `started_at`, `ended_at`, `sensor_config`, `upload_fraction` | 50 | 是 |
| `obstacles.csv` | `obstacle_id`, `trip_id`, `frame_start`, `frame_end`, `type`, `review_state`, `outcome` | 30 | 是 |
| `test_windows.csv` | `window_id`, `region`, `route_id`, `visibility_band`, `permit`, `sensor_config`, `capacity`, `status` | 24 | 是 |
| `weather.csv` | `station_id`, `region`, `observed_at`, `rain_mm`, `visibility_km`, `station_coverage` | 47 | 否 |
| `review_events.csv` | `event_id`, `obstacle_id`, `reviewed_at`, `action`, `new_type`, `new_outcome`, `merge_into`, `frame_start`, `frame_end`, `note` | 10 | 否 |
| `closures.csv` | `route_id`, `region`, `closed_from`, `reason`, `permit_after` | 1 | 否 |
| `route_coverage.csv` | `route_id`, `region`, `visibility_band`, `target_type`, `coverage_weight` | 8 | 否 |

输入文件之间通过明确的标识字段关联。记录时间均为 UTC 或 ISO 日期。缺失覆盖、待复核和撤回状态是有效业务事实，不能自动解释为零事件或成功。事件标签、回执、版本和授权范围以各行记录为准。所有示例数值由固定种子构造，仅供本地数据流程开发与测试。

## 字段语义与口径

### 能见度与时间对齐

* `visibility.csv.observation_quality` 取 `validated`、`estimated`、`missing`。只有前两者可用于能见度定档；`missing` 表示观测缺失这一业务事实，对应行程进入“无法定档”清单，而不是被归入任何分级。
* `coverage_fraction < 1` 表示观测只覆盖路线的一段，匹配结果带部分覆盖标记，报告必须与全程覆盖区分。
* 观测站与车辆时钟存在偏差：应用以行程中点与观测时刻的绝对时间差做就近匹配，默认上限 12 小时（CLI 可调）。超上限或同区域无可靠观测的行程不定档。
* `weather.csv` 仅在地面观测无法定档时作为弱证据兜底，结论保留 `fallback_weather` 痕迹，不单独决定定档。
* 能见度分级：`restricted` 为 <1 km，`low` 为 [1, 5) km，`clear` 为 ≥5 km。

### 障碍检测与人工复核

* `obstacles.csv` 是传感器侧检测，一个障碍可横跨多个帧、在多行重复出现；分析以复核后的“场景”为唯一计数单位，同行程帧区间重叠的检测归并为同一场景。
* `review_events.csv` 是按 `reviewed_at` 顺序施加的事件流，动作包括 `confirm`、`reject`、`reclassify`、`merge`、`split`：
  - `reject` 撤回误检，场景保留为 `withdrawn` 供审计，但不进入任何统计；
  - `merge` 把重复检测并入目标检测，帧区间取并集；
  - `split` 收窄帧边界，拆分边界必须落在原检测帧区间内；
  - `reclassify`/`confirm` 可改写类型与结果，场景进入 `confirmed` 终态。
* 三条不可互换的口径：低能见度行程数（按可靠观测定档）、积水场景数（复核后仍成立的 `water` 场景）、有效规避结果数（`confirmed` 且结果为 `avoided`/`intervention`）。`unclear`、`pending`、`revised` 不进入事件率分母。

### 补测窗口、封闭与路线覆盖

* `test_windows.csv.status` 为 `open` 且 `permit` 未过期的窗口才可排程；`held`/`assigned` 已被占用。匹配同时约束区域、能见度分级与传感器配置，`capacity` 是同一窗口可承载的目标上限。
* `closures.csv` 记录道路封闭或许可变更，只影响尚未执行的计划条目；已采集行程仍按当时观测解释，不被后续事件回改。
* `route_coverage.csv` 给出路线对（能见度分级 × 目标类型）的历史覆盖权重，用于评估改选路线的覆盖损失；权重缺失时损失标注为“无法量化”，不得记为零。
