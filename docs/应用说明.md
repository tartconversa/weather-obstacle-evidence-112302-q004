# 应用说明：低能见度道路障碍证据评估与补测计划

本应用把公开功能说明（“新版本针对深积水等道路障碍改善规避能力”）转化为
可复核的内部证据流程。它不引用任何新闻报道中的事故或故障，只回答一个
问题：**现有合成资料在不同能见度与路况下，究竟支持什么结论、缺什么证据、
补测应排到哪里。**

## 1. 设计原则

1. **三类口径在数据结构上分离，无法互换。** 低能见度行程数、积水场景数、
   有效规避结果数分别来自不同对象（行程、复核后场景、确定性结果），报告
   与 JSON 用独立字段承载，禁止用一个数字替代另一个。
2. **没覆盖到的区域显式标为“无证据”，永不报告成表现正常。** 零行程与
   “观测到零事件”是两件事；有行程但无积水场景同样不构成规避能力证据。
3. **观察到的事件率与可外推结论分开。** 规避率的分母只含复核确认且结果
   确定的场景；两侧样本不足或任一侧无证据的版本对比，只能陈述事实，
   标记为不可外推。
4. **时间错位、部分覆盖、复核更正全部留痕。** 每条定档携带观测来源、
   时间差与覆盖标记；每个场景携带全部来源检测与复核事件编号。
5. **封闭与许可变化只作用于未执行计划。** 已采集行程按当时观测解释，
   历史结论不被后续事件回改。

## 2. 模块结构

```
src/low_visibility_obstacle_evidence/
├── models.py       领域模型、枚举与口径常量（分级阈值、成熟度、缺口等级）
├── io_csv.py       CSV 导入、表头/枚举/外键校验、UTC 归一化、SHA-256
├── time_match.py   观测站-行程就近匹配（错位上限、missing、部分覆盖、气象兜底）
├── review.py       复核事件流重放、撤回/合并/拆分/改判、场景去重
├── analysis.py     覆盖矩阵、三口径汇总、版本可比性、证据缺口分级
├── planner.py      窗口匹配、容量争用、改选损失、封闭重评估
├── reporting.py    中文 Markdown 报告、结构化 JSON、计划 CSV
└── cli.py / __main__.py   analyze / plan / reevaluate 三个子命令
```

数据流是单向的：

```
CSV → io_csv 校验 → Dataset
   → time_match 定档 + review 场景重建
   → analysis 覆盖矩阵/对比/缺口
   → planner 排程（可被 closures 反复重评估）
   → reporting 报告/JSON/CSV
```

## 3. 关键业务口径

### 3.1 能见度定档与时间错位

* 以行程中点对同区域观测做就近匹配，默认时间差上限 12 小时
  （`--max-gap-hours` 可调）。并列时按观测时刻、传感器标识确定性选取。
* `missing` 质量观测不能定档；超上限或无观测的行程进入 unknown 清单。
* 地面观测不可用时允许气象站兜底，但带 `fallback_weather` 弱证据标记。
* `coverage_fraction < 1` 的观测只覆盖路线一段，单元内单独计数。

### 3.2 复核更正与场景边界

* 复核事件按 `reviewed_at`（并列按 `event_id`）顺序重放，可审计、可重跑。
* 同行程帧区间重叠的检测归并为一个场景；相邻不重叠即为两个场景。
* `reject` 撤回的检测保留为 `withdrawn` 场景供追溯，但不进任何统计。
* `merge` 取帧区间并集；`split` 边界必须落在原区间内，否则报错。
* 只有 `confirmed` 且结果为 `avoided`/`intervention` 的场景才是有效规避
  结果；`unclear` 与未成熟（`pending`/`revised`）场景不进事件率分母。

### 3.3 覆盖矩阵与版本对比

矩阵单元键为 `(版本, 能见度分级, 区域)`，区域集合包含观测站与窗口覆盖、
但车队从未行驶的区域，避免漏掉零行程缺口。

版本对比每个组合输出：两侧行程数、有效结果数、积水场景数、规避率与差值、
是否可外推、限制说明。下列任一成立即不可外推：

* 任一侧无行程或无有效规避结果；
* 任一侧有效结果少于稳定门槛（默认 3，`--min-valid-results` 可调）；
* 存在上传不完整行程或部分路线覆盖（作为限制保留，不直接否决）。

### 3.4 证据缺口与补测目标

对最新版本的每个 `(区域 × 能见度分级)` 组合按积水规避能力分级：

| 缺口 | 判定 |
| --- | --- |
| `no_evidence` | 零行程，或有行程但无任何积水场景 |
| `immature` | 有积水场景但均未完成人工复核 |
| `thin` | 有效规避结果少于稳定门槛 |
| `covered` | 满足门槛，不生成目标 |

目标携带所需传感器配置（取该区域该版本的主导配置）。

### 3.5 排程、争用与改选损失

* 窗口必须同时满足区域、分级、传感器配置，且 `status=open`、许可有效、
  路线未封闭。
* 多目标竞争同一稀有窗口时，按缺口优先级
  （no_evidence > immature > thin）确定性分配；落选目标进入未满足清单，
  并列出争用对象与候选窗口，而不是只反映总行程数变化。
* 首选路线取历史覆盖权重最高者；被迫改选时记录覆盖损失权重
  （首选权重 − 改选权重）。权重缺失时损失记为“无法量化”，绝不写零。
* `reevaluate` 对未执行条目按最新封闭/许可状态标记 `blocked`；`executed`
  条目保持不变。重评估前校验输入文件 SHA-256，资料已变更则拒绝静默重跑。

## 4. 命令行用法

```sh
# 安装（src 布局）
python3 -m venv .venv && . .venv/bin/activate
pip install -e .

# 仅分析：覆盖矩阵、口径汇总、版本对比、缺口
python -m low_visibility_obstacle_evidence analyze \
    --data-dir data --out-dir out

# 分析 + 排程（评估时点用于判定封闭是否生效）
python -m low_visibility_obstacle_evidence plan \
    --data-dir data --out-dir out --as-of 2026-11-22T00:00Z

# 封闭或许可变化后重评估未执行条目
python -m low_visibility_obstacle_evidence reevaluate \
    --data-dir data --plan-json out/retest_plan.json \
    --out-dir out --as-of 2026-11-26T00:00Z \
    --mark-executed G-001
```

产物：

| 文件 | 内容 |
| --- | --- |
| `analysis_report.md` | 中文评估报告（来源、口径、矩阵、不可外推组合、缺口、排程、边界） |
| `analysis.json` | 结构化分析结论，含资料校验和与全部矩阵单元 |
| `retest_plan.json` | 计划条目、未满足目标、窗口负载、封闭路线、校验和 |
| `retest_plan.csv` | 调度人员用计划表（UTF-8 BOM，含 unmet 行） |

## 6. 安全与资料处理约定

* 所有资料路径显式传入，应用不依赖当前工作目录；CSV 固定以 UTF-8（兼容
  BOM）读取，表头与枚举逐行校验，错误带文件名与行号。
* 不可信数据目录应与应用代码分目录存放；脚本读取外部资料时建议使用
  `python -I`，避免数据目录中的同名模块被解释器加载。
* 报告与 JSON 均记录输入文件 SHA-256，重评估时核对，资料变更须先重新
  `plan`，防止在过期证据上排程。
